# 任務：NanoClaw 型別安全修復

## 先前脈絡
技術債分析發現 17+ 處 `any` / `as any` / `@ts-ignore`，
其中最嚴重的是 `(global as any).__nanoclaw_bot` 跨模組共享。

## 最終狀態
- commit 68e21ea 為最新基準（P1-P3 技術債清理已完成）
- `rateLimitedFetch` 的 `catch (err: any)` 已在 P2 修為 `catch (err: unknown)`

## 目標
消除所有 `any` 型別逃逸，`npx tsc --noEmit` 零警告。

## 具體步驟

### 步驟 1：建立 typed global（改 2 檔）
- 建立 `src/global.d.ts`，宣告：
  ```ts
  import type { Bot } from 'grammy';
  declare global {
    var __nanoclaw_bot: Bot | undefined;
  }
  ```
- `src/telegram.ts` L972：`(global as any).__nanoclaw_bot = bot` → `globalThis.__nanoclaw_bot = bot`
- `src/index.ts` L513：同步修改

### 步驟 2：定義 API 回應型別（改 host-agent.ts）
在 `src/types.ts` 新增：
```ts
interface SSEEvent {
  choices: { delta: { content?: string; tool_calls?: ToolCall[] } }[];
}
interface ToolCall {
  id: string;
  function: { name: string; arguments: string };
}
interface OpenRouterMessage {
  role: 'system' | 'user' | 'assistant' | 'tool';
  content: string;
  tool_calls?: ToolCall[];
  tool_call_id?: string;
}
```
- `host-agent.ts` L224: `tool_calls?: any[]` → `tool_calls?: ToolCall[]`
- `host-agent.ts` L327: `const messages: any[]` → `const messages: OpenRouterMessage[]`
- `host-agent.ts` L682, L783: `[] as any[]` → 定義 `HandoffEntry[]`

### 步驟 3：修復 catch 型別（殘留 2 處）
`catch (err: any)` → `catch (err: unknown)`，內部用：
```ts
const msg = err instanceof Error ? err.message : String(err);
```
> P2 已修復 rateLimitedFetch 的 catch。殘留位置：
- `host-agent.ts` L275: SSE parse 的 catch
- `health-monitor.ts` L49

### 步驟 3b：修復其他 any
- `telegram.ts` L584: `(p: any)` → 定義 PM2 process type
- `telegram.ts` L972: `(global as any)` → 步驟 1 處理
- `auto-commit.ts` L5: `summary: any` → `summary: HandoffSummary`

### 步驟 4：修復 heartbeat.ts PM2 型別
定義 `PM2Process` interface（name, pm2_env.status, monit.memory, monit.cpu）
替換 L29, L98, L104 的 `any[]`

### 步驟 5：修復 decision-agent.ts L196
定義 `DecisionAPIResponse` interface，替換 `as any`
